# Сервис заказов — лабораторная работа № 1 по ООП

## Запуск, виртуальное окружение и зависимости

Нужен **Python 3.10 или новее**: меню использует `match/case`.
Для запуска достаточно стандартной библиотеки Python.
Для автоматических тестов нужны `pytest` и `pytest-cov` из `requirements-dev.txt`.
База данных, сеть, переменные окружения и отдельный сервер не нужны.

После клонирования репозитория перейдите в его каталог.

### Быстрый запуск

```bash
python3 --version
python3 main.py
```

В Windows вместо `python3` можно использовать `py -3` (при установленном
Python 3.10+). Для выхода выберите `0` в главном меню.

### Виртуальное окружение и установка зависимостей

Для работы с проектом и запуска тестов создайте окружение, активируйте его
и установите тестовые зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python main.py
```

В Windows для создания окружения используйте `py -3 -m venv .venv`,
для активации в PowerShell — `.venv\Scripts\Activate.ps1`.
После активации команды установки зависимостей и запуска такие же, как выше.
Для выхода из виртуального окружения выполните `deactivate`.

## О программе

Консольное приложение для создания заказов, учета товаров на складе,
выбора доставки, назначения курьеров и изменения статусов.

Все данные хранятся **только в памяти**. При выходе заказы и изменения склада
теряются; следующий запуск снова загружает начальные данные из `main.py`.

## Начальные данные и конфигурация

Начальный склад задается вызовами `storage.add_items(...)` в `main.py`:

| Товар | Количество | Цена за штуку, руб. |
| --- | ---: | ---: |
| Клавиатура | 10 | 2500 |
| Мышь | 15 | 1200 |
| Роблокс | 5 | 15000 |

Курьеры создаются там же: `1` — Иван, `2` — Алексей.
Чтобы изменить начальный набор товаров или курьеров, отредактируйте `main.py`.
Отдельного конфигурационного файла нет.

Тарифы и сроки задаются классами в `delivery_methods.py`:

| Доставка | Стоимость, руб. | Срок |
| --- | ---: | --- |
| Стандартная | 350 | 3–5 дней |
| Экспресс | 500 | 1–2 дня |
| Самовывоз | 0 | 30 минут |

Итого = сумма стоимости позиций + стоимость доставки.

## Меню

| Пункт | Действие |
| --- | --- |
| 1 | Создать заказ |
| 2 | Показать все заказы |
| 3 | Изменить способ доставки |
| 4 | Назначить свободного курьера |
| 5 | Изменить статус заказа |
| 6 | Добавить товар или установить новый остаток существующего товара |
| 7 | Показать склад |
| 0 | Выйти |

ID заказа и клиента — положительные целые числа. ID заказа должен быть
уникальным в текущем запуске. Имя, телефон и адрес не могут быть пустыми;
формат телефона отдельно не проверяется.

При создании заказа неверный ввод повторяет только текущий запрос:
ранее введенные данные клиента и выбранные позиции сохраняются.
Неизвестный или уже полностью выбранный товар возвращает к выбору названия;
неверное количество — к вводу количества той же позиции.
Названия товаров нечувствительны к регистру. Можно выбрать один товар
несколько раз, но суммарно не больше доступного остатка.
`0` при выборе названия завершает набор позиций; пустой заказ создать нельзя.
Если склад пуст, сначала добавьте товары через пункт `6`.

## Типовые сценарии

### Заказ с доставкой

1. Выберите `1`. Введите ID заказа `1`, ID клиента `1`, имя `Анна`,
   телефон `+79990000000` и адрес `Невский, 1`.
2. Введите название `мышь`, количество `2`, затем `0` для завершения списка.
3. Выберите доставку `1` (стандартная). Итого: `2750` руб.
4. Через пункт `4` укажите ID заказа `1` и ID курьера `1`.
5. Через пункт `5` последовательно задайте для заказа `1` статусы
   `подтвержден`, `в пути`, `доставлен`.
6. Пункт `2` показывает заказ. Курьер снова свободен,
   на складе осталось 13 мышей.

### Самовывоз

При создании выберите доставку `3`. Курьер не нужен и не может быть назначен.
Через пункт `5` проведите заказ по статусам:
`подтвержден` → `готов к самовывозу` → `завершен`.

### Отмена и возврат товаров

Создайте заказ с двумя мышами и через пункт `5` задайте статус `отменен`.
Списанные при создании товары возвращаются на склад, назначенный курьер
освобождается. Заказ и его позиции остаются в списке для просмотра.
Повторная отмена отклоняется и не увеличивает остатки еще раз.
Возврат сохраняет текущую цену товара на складе.

### Изменение склада и доставки

В пункте `6` для существующего товара вводится **новый абсолютный остаток**,
а не количество для прибавления. Остаток может быть нулевым.
Для нового товара нужны положительное количество и конечная неотрицательная цена.

Через пункт `3` можно изменить доставку созданного или подтвержденного заказа.
При переходе на самовывоз назначенный курьер освобождается.

## Допустимые переходы статусов

Введите статус текстом, как в таблице (например, `отменен`, без буквы `ё`).

| Текущий статус | Следующий статус |
| --- | --- |
| создан | подтвержден, отменен |
| подтвержден | в пути (с курьером), готов к самовывозу (самовывоз), отменен |
| в пути | доставлен, отменен |
| готов к самовывозу | завершен, отменен |
| доставлен, завершен, отменен | Переходов нет |

По правилам этой учебной модели отмена разрешена даже в пути и сразу
возвращает товары на склад. Отменить доставленный или завершенный заказ нельзя.
Правила переходов находятся в `status_flow.py`, ограничения доставки — в `order.py`.

## Тестирование

После настройки окружения и установки зависимостей, описанных в начале README,
выполните из корня репозитория:

```bash
python -m pytest
```

Тесты используют pytest, фикстуры, параметризацию и подмену консольного ввода;
ручной ввод не нужен. Каждый тест получает независимое состояние.

Проверки разделены по файлам:

| Файл | Что проверяется |
| --- | --- |
| `tests/test_entities.py` | Клиент, курьер, позиция заказа: свойства, валидация, изменение состояния |
| `tests/test_collections.py` | Коллекции заказов и курьеров, поиск, дубликаты, доступность |
| `tests/test_storage.py` | Добавление, списание, возврат, удаление, остатки, цены, копии данных |
| `tests/test_delivery.py` | Контракт способов доставки, тарифы и сроки |
| `tests/test_order.py` | Заказ, сумма, позиции, назначение курьера, изменение доставки, матрица переходов статусов |
| `tests/test_console.py` | Все команды меню, ввод, вывод, обработка ошибок |
| `tests/test_workflows.py` | Сохранение заказа при ошибках ввода, отмена, возврат товаров, завершение заказа |
| `tests/test_main.py` | Полный сценарий доставки и запуск `main.py`, в том числе в отдельном процессе |

Полный отчет с покрытием строк и ветвей:

```bash
python -m pytest --cov --cov-report=term-missing
```

Настройки находятся в `pytest.ini` и `.coveragerc`. Покрытие измеряется для всех
модулей приложения; тесты и `.venv` в него не входят. При запуске с `--cov`
установлен минимальный порог 99%. Непокрытые строки и ветви видны в отчете:
это защитные проверки состояния `OrderItem`, которое нельзя получить через
его публичный интерфейс, и ветвь `add_item`, ожидающая `False` от проверок,
которые возвращают `True` либо выбрасывают исключение.

Запуск отдельной группы или сценария:

```bash
python -m pytest tests/test_storage.py -v
python -m pytest -k cancel -v
```

Для ручной проверки ошибок при создании введите `abc` вместо ID, пустое имя,
несуществующий товар, количество больше остатка или доставку `9`.
Приложение должно повторить соответствующий запрос и сохранить предыдущие данные.

## Структура проекта

- `main.py` — начальные данные и запуск.
- `console_app.py` — меню, ввод и координация операций заказа со складом.
- `order.py`, `order_item.py`, `client.py` — заказ, позиция и клиент.
- `courier.py`, `couriers.py`, `orders.py` — курьер и коллекции объектов.
- `storage.py` — остатки, цены, списание и возврат товаров.
- `delivery_methods.py` — способы доставки.
- `constants.py`, `status_flow.py` — статусы и допустимые переходы.
- `tests/` — автоматические проверки на pytest и общие фикстуры.
- `requirements-dev.txt`, `pytest.ini`, `.coveragerc` — зависимости и настройки тестирования.
